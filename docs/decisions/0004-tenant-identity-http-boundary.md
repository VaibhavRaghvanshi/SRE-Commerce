# ADR 0004 — Tenant ownership, live Identity authorization and local infrastructure

Status: approved local Tenant backend implemented and verified; waiting for the next owner checkpoint.

Tenant owns its SQL schema, onboarding/lifecycle, settings/branding metadata, locations/domains, immutable plan versions, subscriptions/limits, module configuration, audits and minimal transactional outbox. It does not read Identity tables, create a competing identity system, render themes, collect payments or deploy listed modules. Shared service database/query filters are implemented first; dedicated tenant databases remain a future strategy.

Tenant uses the standard Identity-issued OpenIddict bearer token. A configured trusted Identity HTTP endpoint validates that token and supplies current account/platform/membership context on each request. Token audience/scope and current session are required; Tenant never trusts unvalidated JWT payloads or tenant headers. This avoids stale authorization and extra signing-key/discovery mapping in this local slice, at the cost of a synchronous Identity dependency and added latency. Production requires HTTPS, timeout/fail-closed behavior, sufficient Identity capacity and later tracing; no cached role fallback is allowed.

Activation idempotently provisions an owner through Identity under the current stored platform administrator's delegated bearer. Tenant then commits activation locally. Failure before Tenant commit leaves no active business authority; retry converges. No cross-database transaction or implicit service-account privilege is introduced. Repeating an unchanged active membership provisioning does not revoke that user's sessions; actual membership changes still revoke them.

Serializable aggregate writes plus SQL rowversion protect configuration and local quotas. Slug/request/domain uniqueness is enforced by SQL. Audits and minimal outbox events commit with mutations; broker delivery is intentionally not claimed until a consumer is approved. No RabbitMQ, Redis/Valkey or Kafka is needed for this phase.

DNS TXT ownership checks use DnsClient 1.8.0, Apache-2.0, with bounded queries and no domain HTTP fetch. Tests substitute deterministic TXT responses and do not publish DNS records. References: [official package/license metadata](https://www.nuget.org/packages/DnsClient/1.8.0), [library API](https://dnsclient.michaco.net/docs/DnsClient.IDnsQuery.html). Microsoft EF/OpenAPI use existing 10.0.14 pins; explicit patched cryptography versions retain the verified advisory fix.

The owner separately approved a dedicated Tenant container SQL login. The script grants only Tenant DML and verifies no schema-creation or Identity/legacy DB access. Secrets remain local. Compose's explicit Tenant overlay keeps new required configuration separate from the working Identity profile. Final verification: Identity 24/24 tests, Tenant 28/28 tests, 34 live container checks, both API images/non-root healthy runtime, and Tenant backup/restore/CHECKDB passed. Source stores are preserved; runtime/resource observations and limitations are in the [completion report](../architecture/tenant-completion-report.md). No GitHub push is authorized.
